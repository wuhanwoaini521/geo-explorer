# Gate 3.5 — READY FOR HUMAN UX REVIEW

## 评审范围

本轮以第一次使用产品、只想了解地貌并按顺序观察珠峰路线的普通用户身份，使用微信开发者工具自动化端口 `ws://127.0.0.1:9420` 在后台完成真实运行体验。没有修改源码、没有提交、没有推送。

评审顺序：

`首页 → 地图图鉴 → 知识页 → 地点详情 → 探索页（珠峰）→ 挑战 → 我的`

探索重点：

`开始探索 → 点击“下一个地貌” → 连续推进 → 到达冰瀑地形观察点 → 打开知识浮窗 → 查看路线索引`

## 二、按严重程度排序的问题清单

### P0：阻断或直接破坏可信度

1. **探索页 → 点击“下一个地貌”推进 → 期望当前点、海拔、路线索引始终指向同一观察点 → 实际发生：** 第一次点击后当前地貌仍是“冰川前缘”，但海拔从路线起点 `5,364 m` 变为 `5,470 m`；视觉复核还发现浮窗显示 `5,700 m`、路线索引出现 `5,870 m`，跨截图口径不一致。普通用户会怀疑路线数据是假的。**严重程度：P0。**

2. **地图页 → 查看路线和点击 BC/底部附近节点 → 期望：** 每个节点清楚可见且路线经过节点 → **实际发生：** BC 节点被底部详情卡遮住，路线虚线没有稳定穿过节点圆点，部分节点贴近屏幕边缘。**严重程度：P0。**

3. **我的页面 → 查看完成后的进度 → 期望：** 知道“完成了多少、总共有多少” → **实际发生：** `1 完成探索 / 4 已获知识 / 1 挑战次数` 没有分母或总进度；`达到 8849 m / 8848.86 m` 看起来像超过峰顶。**严重程度：P0。**

4. **我的页面 → 误触底部操作 → 期望：** 破坏性操作需要明显的二次确认或弱化 → **实际发生：** “清空本地记录”和“数据来源与许可”同为同尺寸按钮，清空记录过于容易误触。**严重程度：P0。**

### P1：明显影响完成任务或理解下一步

1. **首页 → 在搜索框输入“珠峰” → 期望：** 只显示珠峰相关结果或明确提示无匹配 → **实际发生：** `query` 已变为“珠峰”，但 `scenes` 仍是珠穆朗玛峰、马里亚纳海沟、大峡谷、富士山 4 项。**严重程度：P1。**

2. **首页 → 首屏向下浏览 → 期望：** 地点卡、统计和底部导航互不遮挡 → **实际发生：** 底部 TabBar 覆盖内容，最后区域和统计数字被压住；首屏英雄区过高，主要地点入口被下压。**严重程度：P1。**

3. **地图页 → 点击一个路线节点 → 期望：** 选中态明显，预览卡内容和节点一致 → **实际发生：** “南峰”预览标题变化，但缩略图仍使用珠峰同一张图，描述也偏通用；选中态弱，用户不容易确认切换成功。**严重程度：P1。**

4. **探索页 → 完成一次推进 → 期望：** 当前点、下一观察点、当前位置在画面上形成单一关系 → **实际发生：** 当前地貌、下一观察点、底部进度和路线节点需要来回对照；提示同时写“上滑查看下一个、下滑返回上一个”，但页面又提供“上一个/下一个地貌”按钮，主操作不够单一。**严重程度：P1。**

5. **探索页 → 知识浮窗出现 → 期望：** 可关闭、可继续，且不遮挡核心路线 → **实际发生：** 关闭按钮对比度弱；浮窗海拔和主场景海拔口径不一致；浮窗出现时会盖住其他探索控件，用户需要先处理浮窗才能继续看路线。**严重程度：P1。**

6. **知识页 → 第一次打开 → 期望：** 看到推荐知识或知道如何开始筛选 → **实际发生：** 默认落在“人文历史”，而“雪线”搜索与“生态环境”分类均为空，没有解释为什么没有结果，也没有推荐入口。**严重程度：P1。**

7. **地点详情 → 浏览完概览 → 期望：** 立即知道下一步是看知识、进入观察还是参加挑战 → **实际发生：** “进入探索”入口在较下方，首屏看不到；没有一个明确的“下一步”主行动。**严重程度：P1。**

8. **挑战页 → 完成挑战 → 期望：** 结果页告诉用户下一步继续学什么 → **实际发生：** 结果能看懂，但主要只有“再来一轮/换个难度”，没有“回到刚才的地貌”“查看错题/知识”“继续探索”的学习闭环。**严重程度：P1。**

9. **跨页面 → 通过底部导航进入地图、知识、挑战、我的 → 期望：** TabBar 可发现、可点击、激活态与页面一致 → **实际发生：** 本轮自动化无法稳定选择自定义 TabBar 内部的 `.tab` 元素，因此知识、挑战、我的使用直接切页验证；该限制不能证明人工点击一定失败，但说明导航可测试性和可发现性仍需人工确认。**严重程度：P1。**

### P2：轻度困惑或视觉负担

1. **地图页 → 看右侧“图鉴/地形”工具 → 期望：** 明确知道是按钮及当前模式 → **实际发生：** 竖排短文字更像装饰或状态，按钮边界不明显。
2. **路线索引 → 查看当前项 → 期望：** 一眼知道当前位置和已完成范围 → **实际发生：** 主要依靠蓝色圆环，没有“当前位置/已观察”的文字；底部孤立圆点和空白区域像加载未完成。
3. **挑战页 → 选择答案 → 期望：** 选中后有足够的确认感，必要时可退出 → **实际发生：** 点击后立即判分，没有确认步骤，也没有明显退出/跳过入口。
4. **首页/详情/探索 → 阅读辅助文案 → 期望：** 在手机尺寸上轻松阅读 → **实际发生：** 分类标签、环境数据、探索提示和部分节点文字偏小偏淡，压在亮色雪景上时可读性下降。
5. **我的 → 区分收藏与记录 → 期望：** 明白收藏是书签、记录是历史 → **实际发生：** 两个区域都出现珠穆朗玛峰，首条数据看起来像重复内容；收藏只有心形，没有“已收藏”文字。

### P3：细节优化

1. 首页分类横向滚动没有明显提示，右侧标签被裁切。
2. 首页和探索页的装饰性 `GEO` 标识占用了一部分垂直空间，但没有提供额外理解价值。
3. 个人页副标题和辅助信息偏小偏灰；头像 `GE` 容易让人以为可编辑，但没有操作反馈。

## 三、三个维度评分

### 易用性：2 / 5

单页基本能打开，搜索、分类、收藏、路线节点、答题和结果都有可操作反馈；但第一次用户很难依靠产品自身完成“我现在在哪、下一步去哪”的闭环。首页搜索结果未过滤，地图节点被卡片遮挡，探索和知识入口需要跨层级寻找，导航栏也没有完成稳定的人工点击验证。

### 文案可读性：3 / 5

中文文案总体能读懂，`开始探索`、`下一个地貌`、`继续探索`、`查看成绩`等动作词明确；不过海拔与地点名不一致、`上滑/下滑`和按钮操作并存、`完成探索/达到 8849 m/100%`缺少口径说明，造成理解风险。手机截图中小字和低对比度文字较多。

### 登山/地貌观察交互：2 / 5

点击后进度确实从 0% 推进到 3%，连续推进后能到达“冰瀑地形”，也能弹出雪线知识浮窗，说明核心状态不是静态页面；但当前点、下一点、海拔、路线索引没有保持可信的一致关系。路线更像“逐步切换地貌”的演示，尚不足以让用户直观理解自己沿着哪条山脊从哪里走到哪里。

## 四、最影响体验的 Top 5 改进建议

1. **先建立一份唯一的观察点数据表。** 每个节点只从同一数据源生成名称、海拔、缩略图、路线坐标、当前/下一状态和知识关联；地图预览、探索 HUD、路线索引、知识浮窗、完成页全部引用这份数据，禁止各页面自行拼海拔和地点文案。

2. **重做地图节点可见性和选中反馈。** 把底部预览卡避开 BC 节点；让虚线路径严格穿过节点；选中节点增加明确的高亮和“当前观察点”标签；预览卡图片必须随节点更换，不能所有节点都复用珠峰同一张图。

3. **把探索页的主任务收敛成一个动作。** 只保留“下一个地貌”作为主 CTA，并把“上一个地貌/地貌索引/关闭浮窗”放成次级操作；在当前节点旁直接显示“下一观察点：冰瀑地形”，完成切换后给出短暂、可读的“已到达”反馈。

4. **把每个学习阶段的下一步接起来。** 地点详情主按钮进入观察；观察点知识浮窗提供“看懂这处地貌 → 继续观察”单一主线；随堂题结果提供“查看解析/回到观察”；挑战结果提供“继续学习/返回地貌”，让用户不会在完成后掉出流程。

5. **统一首次用户的进度口径与危险操作。** 统计改成“已完成 1 / 共 1 个探索”“已解锁 4 / 共 N 条知识”；海拔统一保留同一精度和含义；“清空本地记录”改为低强调文字按钮并增加二次确认；路线索引增加“已观察/当前/待观察”文字状态。

## 五、空状态、错误与生命周期观察

- 首页搜索未呈现真正的过滤结果，未能验证“无结果”是否有针对性空状态。
- 知识页在“雪线”和“生态环境”场景能进入空状态，文字为“没有匹配的知识条目 / 试试其他关键词或分类”，但缺少推荐或一键清除搜索。
- 视觉上使用了图片兜底结构，但本轮未主动断网或人为触发所有图片错误分支，因此图片失败兜底不作为“已完全验证”结论。
- 探索推进和定时状态在本轮未出现卡死；连续推进、知识提示、路线索引可以完成。但未做长时间后台切换、快速重复点击、页面销毁期间定时器压力测试。
- 本轮未运行类型检查、单元测试和构建，因为 Gate 3.5 明确要求只做体验评审，不修改代码；不能把之前其他轮次的测试结果当成本轮自动化验证。

## 六、局限与数据状态

- 测试使用的是当前本地运行状态，进入时已有 `1` 条完成探索和 `4` 条已获知识，不是清空存储后的严格新用户基线；本轮又完成了 1 次挑战并收藏了珠穆朗玛峰。因此“我的”页用于评估信息表达和完成后反馈，不用于评估空白新用户首次进入状态。
- 所有截图均来自后台自动化，无可见浏览器、无可见微信窗口、无抢焦点操作。
- 视觉判断由当前运行截图和视觉复核代理共同完成；未覆盖真实设备触控、屏幕阅读器、网络慢速和真实用户访谈。
- 自动化对自定义 TabBar 内部节点选择不稳定，所以跨 Tab 的人工可发现性需要产品/设计人员在微信开发者工具或真机上补一次手点确认。
