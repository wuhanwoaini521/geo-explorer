## 1. 文档目的

本文档把赛事规则转化为 Geo Explorer 的产品、技术、发布和材料验收要求。自本基线建立后，所有参赛版本的需求取舍、实现和验收均应优先满足本文档。

文档中的要求分为三类：

- **赛事硬性要求**：未满足将导致作品无法参赛或无法完成提报。
- **项目参赛要求**：根据评审标准为 Geo Explorer 制定的内部交付要求。
- **待官方确认项**：公开资料无法完整确认，必须在赛事平台登录后的提报页面或官方答疑群中复核。

若赛事官网、组委会邮件或官方答疑给出更新规则，以最新官方规则为准，并同步更新本文档。

## 3. 赛事硬性要求

### 3.1 资格要求

- [ ] 参赛者已在赛事平台完成实名报名。
- [ ] 队伍成员不超过 3 人。
- [ ] 参赛作品为微信小程序，不是小游戏。
- [ ] 作品具备原创性，不侵犯第三方著作权、商标权、肖像权、数据权利或其他合法权益。
- [ ] 使用的开源代码、地图数据、照片、纹理、字体和 AI 生成内容均保留来源、许可和必要的署名记录。

### 3.2 上线要求

- [ ] 小程序在 2026-10-17 前通过微信公众平台审核并正式发布。
- [ ] 线上版本可通过小程序名称、小程序码或赛事提交入口正常访问。
- [ ] 核心流程不依赖开发者工具、体验权限、白名单账号或本地服务。
- [ ] 评审期间不出现云环境到期、欠费停服、域名失效、证书失效或资源链接过期。
- [ ] 线上版本至少稳定运行至 2026-12-15；若官方赛程延后，应覆盖新的赛事结束日期。

### 3.3 作品提报要求

当前公开资料显示，提报至少需要线上小程序信息、小程序码和作品说明材料。以下字段需登录提报页面逐项确认：

- [ ] 线上小程序 AppID。
- [ ] 小程序名称、版本、类目和正式上线状态。
- [ ] 可直接扫码访问的小程序码。
- [ ] 作品名称、作品简介、目标用户和解决的问题。
- [ ] 创作背景、创作思路、实践过程和技术实现说明。
- [ ] 团队成员与职责。
- [ ] AI 能力说明，包括使用场景、模型或服务、数据来源和安全边界。
- [ ] 演示视频、截图、路演材料等赛事页面要求的附件。
- [ ] 文件格式、单文件大小和总大小符合提报页面限制。

公开整理资料提到说明文档可能限制在 100 MB 内，但尚未从登录后的官方提报表单直接确认，不能把该数值视为最终要求。

## 4. 评审标准及项目应对

赛事公开的四项评审维度没有公布权重，项目必须同时覆盖，不能只追求视觉或技术复杂度。

| 评审维度 | 评委关注点 | Geo Explorer 对应要求 | 验收证据 |
| --- | --- | --- | --- |
| 产品实用性 | 是否解决真实问题，目标用户和场景是否清晰 | 聚焦地理学习和探索，将抽象知识转化为可探索、可理解、可复习的体验 | 用户场景说明、核心流程、可用内容 |
| 产品创新性 | 是否有新的产品方式或技术应用 | 用可交互地球、路线探索、跨世界知识图谱和情境化 AI 导览形成差异 | 功能演示、技术说明、对比说明 |
| 用户体验感 | 是否易用、稳定、清晰、流畅 | 保证主场景沉浸感、层级清楚、加载可感知、弱网可恢复、真机交互稳定 | 真机截图、录屏、性能和异常验证 |
| 作品完整度 | 是否为可上线、可持续体验的完整产品 | 四个世界、图鉴、知识、问答、个人进度与 AI 能力形成闭环 | 正式版小程序、完整测试清单、说明文档 |

## 5. Geo Explorer 的参赛产品定义

### 5.1 目标用户

- 对地理、地貌和自然探索感兴趣的普通用户。
- 需要直观理解海拔、深度、地形演化和极端环境的学生与亲子用户。
- 希望通过短时互动获取可靠地理知识的微信用户。

### 5.2 核心价值

Geo Explorer 通过四个探索世界，将地点、路线、环境变化、知识条目和挑战题组织成连续体验：

1. 在地球上选择目的地。
2. 沿真实地貌或路线推进探索。
3. 在关键节点观察环境与学习知识。
4. 将不同世界的现象连接进知识图谱。
5. 通过问答和个性化复习验证理解。

### 5.3 参赛版本必须覆盖的世界

- [ ] 珠穆朗玛峰攀登。
- [ ] 马里亚纳海沟下潜。
- [ ] 富士山攀登。
- [ ] 科罗拉多大峡谷下潜。

若某个世界无法在截止日期前达到完整上线质量，应缩减该世界的非核心内容，不得保留明显断链、空白页、无图条目或不可完成的主流程。

## 6. AI 能力要求

赛事规则使用“鼓励合理应用 AI”的表达，AI 不一定是形式上的资格门槛，但“与 AI 共生”是赛事主题。为了保证竞争力，Geo Explorer 参赛版必须提供用户可直接体验、与核心场景结合的 AI 能力。

### 6.1 首选功能：AI 地理考察向导

AI 向导应基于用户所在的世界、当前位置、已解锁知识和提问进行情境化讲解：

- 回答当前地貌、气候、生物、海拔或深度相关问题。
- 将回答限制在项目知识库、知识图谱和已核验资料范围内。
- 提供对应知识条目或资料来源，避免无依据回答。
- 支持适龄、普通和专业等解释层级。
- 根据用户探索记录生成个性化复习建议或挑战题。
- 无法确认时明确表达不确定性，并引导用户查看已核验内容。

### 6.2 AI 实现边界

- [ ] 模型密钥只能保存在云函数或安全服务端，禁止写入小程序代码、配置文件或构建产物。
- [ ] 小程序端只提交完成任务所需的最小上下文，不上传不必要的个人信息。
- [ ] AI 回答有长度、超时、频率和成本限制。
- [ ] 模型不可用时回退到项目现有知识卡，不阻断探索主流程。
- [ ] 对模型输出进行结构校验、内容安全处理和错误兜底。
- [ ] 对关键事实优先展示项目已核验内容，不能把模型生成内容当作唯一事实来源。
- [ ] 记录使用的模型、提示词策略、检索范围和安全措施，供作品说明和答辩使用。

### 6.3 赛事赠送 Token 的使用原则

赛事赠送的 Coding Plan Token 在正式条款确认前，只视为开发辅助资源，不默认具备线上小程序生产调用授权。

- 不得把 Token 写入前端。
- 不得把临时额度作为线上核心功能的唯一依赖。
- 如需将其用于正式版运行，必须先向组委会确认生产使用范围、有效期、限流和数据条款。

## 7. 发布与包体要求

### 7.1 平台门槛

- 主包和单个分包不得超过微信平台当前上传限制。
- 内部目标：主包不超过 1.5 MB，以通过开发者工具代码质量检查并降低启动耗时。
- JS、WXML 和 WXSS 使用发布压缩配置。
- 单张本地图片或音频原则上不超过 200 KB；必要例外必须有明确原因且不影响包体上限。
- 不上传未使用的组件、代码、调试文件、素材源文件、评审资源和高分辨率对照图。

### 7.2 当前已知问题

截至 2026-09-15，`dist/miniprogram/` 约 27.8 MiB，其中图片约 26.7 MiB，且当前没有分包配置。以下资源是主要包体风险：

- 4096 地球彩色贴图约 10.2 MiB。
- 2048 地球彩色贴图约 3.66 MiB。
- 珠峰主视觉约 2.85 MiB。
- 其余高度图、镜面图、地点照片和知识图片约数 MiB。
- `project.config.json` 当前关闭 JS 压缩。
- 探索页注册了实际未使用的 `progress-bar` 自定义组件。

### 7.3 参赛版发布策略

按以下顺序处理，先得到可审核的正式版本，再考虑长期架构：

1. 将地球贴图、主视觉和大型内容照片迁移到 CloudBase 云存储或稳定的 HTTPS 对象存储。
2. 主包只保留代码、小图标和轻量本地兜底图。
3. 开启 JS、WXML、WXSS 压缩。
4. 删除确定未使用的组件和资源。
5. 重新扫描主包；若仍超过内部目标，再将非 TabBar 页面拆入普通分包。
6. 配置并验证合法域名、HTTPS、缓存、弱网超时和加载失败回退。
7. 在 iOS 和 Android 真机上验证远程图片和 Canvas/WebGL 贴图加载。

不能只通过开启“上传时忽略未使用文件”处理包体，因为当前存在动态拼接的图片路径，自动依赖分析可能误删运行时资源。

## 8. 云服务与成本基线

因为作品必须正式上线并跨越初审和决赛阶段，不能依赖发布后很快到期的临时环境。

- [ ] 云环境有效期覆盖到至少 2026-12-15。
- [ ] 关闭不受控的超限按量付费，或设置明确的预算告警和日限额。
- [ ] 资源访问失败时小程序仍可进入核心页面并看到本地兜底内容。
- [ ] 对图片设置长期缓存和版本化 URL，减少重复流量。
- [ ] 定期检查云存储、CDN、云函数和模型调用量。

当前建议为 CloudBase 个人版或等价的稳定资源方案。按公开参考价 19.9 元/月估算，从正式上线维护至赛事结束应预留约 40 至 60 元。实际费用和配额以购买页面为准。

## 9. 内容、隐私与审核要求

### 9.1 内容与素材

- [ ] 地貌、地点和探索场景主视觉使用符合项目规范的实景照片。
- [ ] 科研图和示意图只用于机制讲解，不作为地点封面。
- [ ] 每个上线素材都有来源、许可、用途和处理记录。
- [ ] AI 生成或修改的素材明确记录生成方式，并完成人工检查。
- [ ] 地理事实、海拔、深度、路线和历史信息有可追溯来源。
- [ ] 不包含无法证明许可的照片、地图、字体或商业标识。

### 9.2 隐私与安全

- [ ] 隐私政策与实际收集、使用的数据一致。
- [ ] AI 提问、收藏、探索进度和日志遵循最小收集原则。
- [ ] 如果数据发送至云函数或第三方模型，用户可在隐私说明中了解用途。
- [ ] 不在客户端保存密钥、管理凭证或可被滥用的云资源地址。
- [ ] 生产环境关闭调试入口、内部查询参数和高分辨率测试开关。

### 9.3 微信审核

- [ ] 小程序类目与实际内容和功能一致，所需资质已准备。
- [ ] 页面不存在测试文案、空白内容、不可用按钮或仅开发者可访问的功能。
- [ ] 登录、授权、隐私弹窗和拒绝授权后的体验符合微信要求。
- [ ] AI 功能的服务内容、用户输入和生成结果符合上线审核要求。
- [ ] 首次提审不晚于 2026-10-05，给驳回修改和二次审核留出时间。

## 10. 质量验收矩阵

### 10.1 核心流程

- [ ] 首次进入地图并看到可用地球。
- [ ] 选择四个目的地并进入对应探索。
- [ ] 完成路线推进、航点查看和状态保存。
- [ ] 打开地点详情、知识详情和知识图谱关联。
- [ ] 完成随堂问答和挑战。
- [ ] 收藏、记录和个人页状态正确。
- [ ] AI 向导能够结合当前场景回答，并在失败时正常回退。

### 10.2 渲染与视觉

- [ ] WebGL 主路径可用。
- [ ] Canvas 2D 兜底路径可用。
- [ ] 地点投影、点击、选择状态和拖拽旋转一致。
- [ ] 图鉴打开时地球层级正确，关闭后可恢复。
- [ ] 远程贴图加载前有合理占位，失败后无白屏或透明球体。
- [ ] 主场景、卡片、弹窗、导航和安全区域在常见屏幕尺寸下无明显问题。

### 10.3 网络与异常

- [ ] Wi-Fi、移动网络和弱网下均可进入核心流程。
- [ ] 云存储、云函数和模型请求设置超时与重试边界。
- [ ] 图片加载失败、AI 超时、返回格式错误和额度耗尽均有用户可理解的反馈。
- [ ] 不因单个远程资源失败阻断整个页面。

### 10.4 工程验证

- [ ] `npm run typecheck` 通过。
- [ ] `npm run build` 通过，`dist/miniprogram/` 与源码同步。
- [ ] `npm test` 通过。
- [ ] `npm run content:validate` 通过。
- [ ] 微信开发者工具代码质量检查无发布阻塞项。
- [ ] 微信开发者工具依赖分析和包体分析符合目标。
- [ ] 完成正式版真机截图和核心流程录屏。
- [ ] 正式上线后再次扫码验证，而不是只验证开发版或体验版。

## 12. 范围控制原则

在提报截止前，所有新需求按以下顺序判断：

1. 是否影响正式上线硬门槛。
2. 是否直接增强四项评审维度。
3. 是否能在不破坏现有核心流程的情况下完成并验证。
4. 是否增加审核、云成本、内容合规或运行稳定性风险。

满足上线、核心闭环、AI 场景和可验证性后，停止扩大功能范围。不能为了增加功能数量牺牲作品完整度和正式上线时间。

## 13. 上线放行标准

只有同时满足以下条件，参赛版本才允许提交微信审核：

- [ ] 主包和所有分包符合微信上传限制，主包目标不超过 1.5 MB。
- [ ] 所有构建、类型检查、单元测试和内容校验通过。
- [ ] 四个世界至少各有一个完整、可完成的探索路径。
- [ ] AI 能力可以在正式环境使用，密钥安全，失败可回退。
- [ ] 所有远程媒体使用生产地址，且有加载失败处理。
- [ ] 隐私政策、类目、素材许可和来源记录完整。
- [ ] iOS、Android 真机核心流程通过。
- [ ] 没有测试入口、临时 Token、个人配置或调试资源进入构建产物。
- [ ] 小程序码、作品说明、截图和演示材料已准备。
